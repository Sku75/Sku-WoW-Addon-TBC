SkuMapper 5.0 (Karten-Tool fuer Sku)

Diese Anleitung gibt es auch auf Englisch (README.txt) und Franzoesisch
(LISEZMOI.txt).

Wozu
- Zum Erstellen und Bearbeiten von Kartendaten (Wegpunkte, Routen) fuer das SkuAddon.
  Sichtbares Tool, gedacht fuer sehende Helfer.
- Jede Datenbasis hat eine KARTENNUMMER. Das Tool merkt sich, auf welcher Nummer
  die eigene Arbeit aufsetzt, und gibt sie bei der Abgabe mit — so kann nichts
  verwechselt oder ueberschrieben werden. Es darf frei ueberall gemappt werden.

Einbau
1. Den Ordner SkuMapper nach Interface\AddOns kopieren und das Addon aktivieren.
   Nach einem Blizzard-Patch ggf. "Veraltete AddOns laden" im AddOn-Fenster setzen.
2. Karte oeffnen: Escape, Tastenbelegung, Kategorie Other (Sonstiges), Eintrag
   "Open Sku Minimap" eine Taste zuweisen, dann diese Taste druecken.

Neue Kartendaten bekommen (der normale Weg seit 5.0)
1. Das Kartendaten-Paket vom Sku-Team ("SkuMapper-Datenpaket-Karte-N.zip") in
   den Download-Ordner oder auf den Desktop legen.
2. Im SkuMapper-Addon-Ordner die Datei InstallMapData.bat doppelklicken.
   ACHTUNG: Vorher eigene, noch nicht abgegebene Arbeit abgeben (siehe unten)!
3. Danach im Spiel:  /sku reset  und dann  /reload  — fertig, die neue Karte
   ist aktiv (WoW muss nicht neu gestartet werden).

Kartendaten abgeben (der normale Weg seit 5.0)
1. Im Spiel:  /sku save <kurzer Kommentar>   (z.B.: /sku save Westfall Wegpunkte)
   Geht auch per Knopf "Save hand-in" auf dem Kartenoptionsfeld oder per Taste
   "Save map data for hand-in" (beide nutzen den letzten Kommentar weiter).
2. Im Spiel:  /reload                        (erst das schreibt die Daten auf die Platte)
3. Im SkuMapper-Addon-Ordner die Datei HandInMapData.bat doppelklicken.
   Sie legt eine ZIP-Datei auf den Desktop.
4. Diese ZIP an das Sku-Team senden. Fertig — kein Kopieren, kein WTF-Ordner.
Es darf frei ueberall gemappt werden; das Zusammenfuehren mit der Arbeit anderer
Mapper uebernimmt das Sku-Team (Wegpunkt fuer Wegpunkt, nichts geht verloren).

Kartendaten (alt)
- Import und Export ueber ein Textfeld (Copy/Paste): /sku import bzw. /sku export.

Neu in 5.0
- Abgabe-Arbeitsablauf: /sku save <Kommentar> + /reload + HandInMapData.bat
  (siehe oben). Der Kommentar hilft dem Team zu verstehen, was gemacht wurde.
- Dafuer gibt es auch einen Knopf "Save hand-in" auf dem Optionsfeld der
  Sku-Karte und eine belegbare Taste "Save map data for hand-in"
  (Tastenbelegung, Kategorie Other/Sonstiges). Beide nutzen den zuletzt per
  /sku save gesetzten Kommentar weiter.
- Neue Kartendaten kommen als "SkuMapper-Datenpaket-Karte-N.zip" und werden
  mit InstallMapData.bat installiert (siehe oben) — kein Datei-Kopieren von
  Hand mehr.
- Jede Datenbasis hat jetzt eine KARTENNUMMER. Das Tool merkt sich, auf welcher
  Nummer die eigene Arbeit aufsetzt, und gibt sie bei der Abgabe mit — so kann
  nichts mehr verwechselt oder ueberschrieben werden.
- Neue Wegpunkte werden mit der Spielphase (Era/TBC/WotLK) gestempelt, in der
  sie gesetzt wurden — die Anniversary-Zeitlinie ist zyklisch und Karten
  unterscheiden sich zwischen den Phasen.
- Franzoesische Namen bleiben erhalten: das Tool kannte bisher nur en/de und
  hat beim Speichern die dritte Namensspalte (frFR) verworfen bzw. Namen mit
  drei Spalten falsch zerlegt. Jetzt werden alle Spalten korrekt behandelt.
- Laedt die Basisdaten aus dem aktuellen Sku-Routenformat (die Datei besteht
  jetzt aus mehreren Abschnitts-Buildern; 4.9 haette daraus leer gestartet).

Neu in 4.9
- Die Basis-Kartendaten werden wieder aus Skus AKTUELLEN Routendaten geladen
  (routedata_global.lua). LoadDefaultMapData war seit der Umstellung auf die neue
  Datenstruktur wirkungslos; eine frische Installation startete leer, und ein
  Export konnte dadurch vorhandene Routen loeschen. Jetzt wird wieder aus den
  ausgelieferten Daten aufgebaut (mit Aufteilung der gepackten en/de-Namen).
- Undo fuer "Kommentar hinzufuegen" korrigiert (es speicherte den Wegpunktnamen
  an der Stelle der Undo-Funktion und lief beim Rueckgaengigmachen auf Fehler).
- Export veraendert die Live-Daten nicht mehr (Kommentare/createdAt): jeder
  Wegpunkt wird vorher kopiert; wiederholte Exporte verschlechtern die Daten nicht.
- Toter Code entfernt (ein ungenutzter /way-Text-Import-Prototyp, ein doppeltes
  SkuSpairs).
- Weiterhin ueber Kopieren/Einfuegen (Export/Import); kompatibel mit Sku 42.

Neu in 4.8
- Export unter neueren Clients repariert: der Aufruf GetAddOnMetadata gibt es dort nicht
  mehr; genutzt wird jetzt C_AddOns.GetAddOnMetadata (mit Rueckfall auf den alten Aufruf).
  Vorher stuerzte /sku export ab ("attempt to call a nil value").
