# SkuCore/auctionHouse.lua

- Purpose: The complete Auction House feature for the legacy TBC-Anniversary AH API (C_AuctionHouse does not exist on this client). It is an AceAddon submodule of SkuCore (`AuctionHouse = SkuCore:NewModule("AuctionHouse", "AceEvent-3.0")`, published as `SkuCore.AuctionHouse`, user-toggleable via RegisterToggleableModule). It owns: the paged/getAll scanner state machine, incremental result-list menus, the hardware-event-gated one-keypress buy path (PlaceAuctionBid via override binding, the Auctionator technique), the sell/post flow with server-result capture, the automated "strategy buy" loop, and the cross-session price-history DB. The file is deliberately single-file but sectioned (SECTION 1-9, table of contents at top); at ~4050 lines it is the largest SkuCore feature file.

## Public API / exports
- Lifecycle: `AuctionHouse:OnEnable` (calls AuctionHouseOnInitialize + AuctionHouseOnLogin), `OnDisable` (stops ticker, unregisters 5 AUCTION_* events, secure-buy teardown), `AuctionHouseOnInitialize` (registers events + creates the OnUpdate watchdog ticker frame), `AuctionHouseOnLogin` (restores serialized AuctionDBHistory), `AuctionHouseOnPLAYER_LEAVING_WORLD` (empty stub).
- Session events: `AUCTION_HOUSE_SHOW` (init per-visit filter, auto-open AH menu via SlashFunc), `AUCTION_HOUSE_CLOSED` (cancel buy, finish scan, reset strategy buy).
- Buy state machine: `AuctionBuyCancel` (cancel all pending timers, bump generation), `AuctionBuyConfirm(x, result)` (thin wrapper building the keypress-buy spec), `AuctionArmKeypressBid(aSpec)` (the SHARED keypress buy: waits for list to settle, then maps ENTER/NUMPADENTER -> SkuAuctionBuyExec, ESCAPE -> cancel button; spec fields x/type/expItemId/expBuyout/expCount/bidAmount/prompt plus optional onSuccess/onRace/onGone/onCancel handlers used by strategy buy).
- Secure-buy internals (public methods because buttons/timers call them): `AuctionSecureBuyExecute` (runs in the hardware event: re-finds the live index, fire-time CanSendAuctionQuery gate, direct PlaceAuctionBid), `AuctionSecureBuyOnCommitted` (switch to verifying, arm 5s timeout), `AuctionSecureBuyResolve(outcome, source, msg)` (single resolution point: server message decides, money-diff only on timeout), `AuctionSecureBuyCancel(announce)`, `AuctionSecureBuyTeardown` (release bindings, restore Sku menu keys, stop capture).
- Result-list pruning after a buy: `AuctionResultsItemEntryFromCursor` (find the group entry by signature .tIndex + .data[19]), `AuctionPruneListAuction(record)` (remove bought/gone auction from dupes + QueryResultsDB, unhook via SkuMenu:Remove, stash cursor target in SkuCore.AuctionPrunePos), `AuctionStayOnResultsEntry` (re-pin cursor after prune).
- Strategy buy: `StrategyBuyStart(itemName, maxPricePerUnit, totalAmount)`, `StrategyBuySearch` (single page-0 unit-price-sorted query via the common scanner), `StrategyBuyProcessResults` (pick cheapest 1-stack candidate, arm shared keypress buy with own handlers), `StrategyBuyStopTimers(sb)`.
- Formatting/tooltip: `AuctionItemNameFormat(itemData, index, addLevel)` (spoken result-line text), `AuctionBuildItemTooltip(itemData, ...)` (scanning-tooltip text + price sections), `AuctionGetPricePerItem(data)` ({bid, buy} per unit, divide-by-zero guarded).
- True GLOBALS (not on the module): `SkuGetCoinText(copper, short, veryShort)` (spoken coin text; `short` param is documented dead), `SkuEpochValueHelper(epoch)` ("N Sekunden/Minuten/Stunden/Tage ago"). Used by other modules too.
- Menu builders: `AuctionHouseMenuBuilder()` (whole AH menu tree: Auktionen with Filter und Sortierung / auctions by item / by search string / strategy buy / full scan; Gebote; Verkaeufe incl. "Neue Auktion" sell flow and own-auction cancel), `AuctionHouseBuildItemSellMenuSub(self, gossipItemTable)` (gold/silver/copper coin price menu -> auction count -> duration -> post), `AuctionHouseBuildItemDBMenu(self, cat, sub, subsub)` (live category browse from SkuDB item data + "All" query entry), `AuctionHouseBuildItemFullScanDBMenu(parent, cat, sub, subsub)` (same for the frozen full-scan DB).
- Result list building: `AuctionGroupResults()` (group QueryResultsDB by formatted name into sorted unique entries with dupes), `AuctionResultsCreateEntry(parent, dataTmp, index)`, `AuctionResultsAppend()` (silent append of later scan pages, cursor-preserving, filter-base aware), `AuctionAnnounceFilterProgress()` (10s "x von y Seiten durchsucht" while letter-filter shows 0 hits), `AuctionHouseResultsMenuBuilder(parent)` (first full build, or "Warten"/"leer" placeholders).
- Scanner: `AuctionScanSetState(state, mode)` (single transition point), `AuctionHouseResetQuery(force)`, `AuctionScanFinish(reason, force)` (canonical scan teardown + breadcrumb), `AuctionCursorInResults(host)` (is the cursor inside this results list), `AuctionHouseStartQuery(continue, type, text, minLvl, maxLvl, page, usable, rarity, getAll, exactMatch, filterData, callback, singlePage)` (THE query entry: refuses new queries while a buy is settling/armed; sets server-side unitprice sort for non-getAll; pcall-guarded QueryAuctionItems; returns false if not sent).
- Full-scan chunked ingest: `AuctionFullScanCooldownRemaining()` (own 16-min timer, minutes left), `AuctionFullScanBeginIngest(batch, count)`, `AuctionFullScanProcessChunk()` (250 rows per frame, 25% announcements), `AuctionFullScanFinishIngest()` (history fold, async serialize, completion announce).
- Result events: `AUCTION_OWNED_LIST_UPDATE` / `AUCTION_BIDDER_LIST_UPDATE` (fill OwnDB/BidDB via shared local ScanSideList), `AUCTION_ITEM_LIST_UPDATE` (dispatcher), `AUCTION_ITEM_LIST_UPDATE_LIST` (browse/getAll ingest, incremental first-page display + append), `AUCTION_ITEM_LIST_UPDATE_BUY` (re-find the exact auction on page 0, skip already-tried matches, hand off to AuctionBuyConfirm; page-0-no-match = "vergriffen" + prune).
- Price data: `AuctionBuildPriceData(sourceDB)` (O(n) per-unit bid/buy buckets per itemId), `AuctionUpdateAuctionDBHistory(sourceDB, targetTable, precomputed)` (fold into low/median/high/points tuples), `AuctionHouseGetAuctionPriceHistoryData(itemID, curDB, histDB)` (spoken vendor/current/history price sections + suggested sell price).
- Internal helper families (file-locals): `_AB*` (buy cleanup/ascend/retry: _ABLog, _ABTrack, _ABClearBuyState, _ABAscendAndVocalize, _ABCleanupAndAscend, _ABFinalizeAllBought, _ABBuyGiveUp, _ABReQueryBuy, _ABContinueOrFinish, _ABRetrySamePurchase); `_ASB*` (secure-buy bindings + server-message capture); `_AS*` (sell-path logging + post-result capture); `SplitCoin`/`CombineCoin`; `Median`; `ScanSideList`; `_AuctionAttachBuyBidChildren(entry, data, fullScan)` (shared Bieten/Kaufen submenus, replaces three former copy-paste blocks); `tStratSay`.

## Key data structures
- Field-index maps: `tQAIindex` (QueryAuctionItems arg positions) and `tAIDIndex` (GetAuctionItemInfo result positions 1-19; addon adds [20]=level, [21]=itemLink, plus `.query` = the originating QueryData and `[19]` reused as the dupes list on group representatives — note [19] shadows the original "query" flag field).
- Result DBs (deliberately GLOBAL, no `local`): `QueryResultsDB` (frozen append-only browse snapshot), `FullScanResultsDB` (+ `FullScanResultsDBHistory` per-scan price fold), `AuctionDBHistory` (cross-session low/median/high/points per itemId, persisted as string). File-local: `BidDB`, `OwnDB`.
- Scanner state: `SkuCore.AuctionScan = {state = "idle"|"waiting"|"paging", mode = "browse"|"buy"|"getAll"|nil}`; `SkuCore.QueryData` (current query args, tQAIindex-shaped), QueryCurrentPage/QueryMaxPage/QueryCallback/QuerySinglePage/QueryCurrentType; `SkuCore.QuerySerializeRunning` (post-scan history serialize); `SkuCore.FullScanIngest` (chunked getAll reader: active/total/processed/dbn/nextPct/reachedEnd + cached hot-path fns; FULLSCAN_CHUNK=250 rows per frame).
- Buy state: `SkuCore.AuctionBuy = {generation, pending, timers[], failCount}` (generation counter kills stale closures; AB_BUY_MAX_FAILS=3); `SkuCore.QueryBuyData/-Type(1 bid,2 buyout)/-Amount/-Bought/-EmptyWaits`; `SkuCore.AuctionSecureBuy = {active, stage("settling"|"trigger"|"verifying"), p(spec), gen, safety, verifyTimer}`; `SkuCore.AuctionPrunePos` (cursor re-pin target after prune).
- Incremental results display: `SkuCore.QueryResultsHost` (menu entry owning the list), `QueryResultsParent`, `QueryResultsByName` (name -> menu entry for label updates), `QueryResultsPartialReady`.
- Strategy buy: `SkuCore.StratBuy` (run state: bought/fails/maxFails=5/triedPrices/purchaseLog/searchFrame/waitTimer), `SkuCore.StratBuyConfig` (menu-edited: itemName/maxGold/maxSilver/maxCopper/amount).
- Frames: `SkuCoreSecureTabButtonAuctions` (OnUpdate ticker: chunk driver, 10s progress speech, getAll 600s + paged 60s-stall/180s-total watchdogs, paged next-page sender), `SkuAuctionSecureBinder` (override-binding owner), `SkuAuctionBuyExec` + `SkuAuctionSecureCancelButton` (hidden buttons the ENTER/ESCAPE overrides click), `SkuAuctionSecureMsgFrame` + `SkuAuctionSellMsgFrame` (server-message capture).

## Events
- AceEvent on the module (registered in OnEnable, unregistered in OnDisable): AUCTION_HOUSE_SHOW, AUCTION_HOUSE_CLOSED, AUCTION_OWNED_LIST_UPDATE, AUCTION_BIDDER_LIST_UPDATE, AUCTION_ITEM_LIST_UPDATE.
- Frame-registered (transient windows only): _ASBMsgFrame listens CHAT_MSG_SYSTEM + UI_ERROR_MESSAGE during buy "verifying" (success = ERR_AUCTION_BID_PLACED; failure = whitelist of 5 ERR_* strings); _ASMsgFrame listens UI_ERROR_MESSAGE, CHAT_MSG_SYSTEM and 4 AUCTION_MULTISELL_*/AH_CLOSED events for 8s after PostAuction (logging only).
- Timers: the OnUpdate ticker frame (SkuCore.AuctionTickerWait 0.03 / AuctionTickerWaitFull 0.20); C_Timer.NewTimer for arm-polling (0.2s), buy verify timeout (5s), safety release (30s), post-buy cursor/announce delays; C_Timer.NewTicker for strategy-buy 4s "Bitte warten".
- No SkuDispatcher subscriptions; no AceComm.

## Entry points
- Menu: AuctionHouseMenuBuilder is the "Auktionshaus" Local-window contributor wired in SkuCore/Core.lua (~line 369, called dot-style with the parent entry as self); AUCTION_HOUSE_SHOW auto-opens it via SkuOptions:SlashFunc(L["short"],Local,Auktionshaus) after 0.3s.

## Invariants & gotchas
- Section ordering constraints (documented at top): SECTION 1 locals first; SECTION 3 defines _ABBuyGiveUp/AuctionBuyConfirm used by SECTION 8; SECTION 4 defines Median used by SECTION 9. Do not reorder when splitting.
- PlaceAuctionBid is HARDWARE-EVENT gated (not taint/secure): it must run inside a real key/click handler (the override-binding click qualifies) AND CanSendAuctionQuery() must be true — it shares the AH throttle with QueryAuctionItems; with the throttle closed the bid is dropped SILENTLY (no money change, no server message). Both gates live in AuctionSecureBuyExecute; do not remove either.
- While AuctionSecureBuy.stage is "settling" or "trigger", AuctionHouseStartQuery returns false on purpose — a new query would rebuild the server list and invalidate the armed buy index.
- After a buy, Sku's own ENTER/ESCAPE menu bindings MUST be restored by re-running SecureOnSkuOptionsMainOption1/2 OnShow (they arm the configurable SKU_KEY_MENULEFTCLICK/-RIGHTCLICK keys) — a plain ClearOverrideBindings leaves the menu keys dead (_ASBRestoreSkuBindings, lines 993-1009).
- AUCTION_ITEM_LIST_UPDATE fires MANY times per server response (streaming): the "waiting" -> "paging" state transition is the dedupe gate; last page is detected by tBatch < 50 (not tCount arithmetic). getAll answers arrive as one giant event and MUST be ingested chunked (250/frame) or the client freezes for seconds.
- ERR_AUCTION_DATABASE_ERROR must NOT count as buy failure — the TBC server emits it spontaneously even on successful buys (whitelist comment, lines 930-937).
- Anniversary quirks relied on: owner field (14) is often permanently nil (never validate on it); server-side SortAuctionSetSort("list","unitprice") before the query makes page 0 the cheapest page — the buy path's "no match on page 0 = auction gone" shortcut depends on it.
- The deprecated-popup unregister only sticks because this file loads AFTER UIParent's OnLoad each session; keep it at file scope.
- getAll watchdog is deliberately 600s (server takes 1-2+ min to answer on Anniversary; the old 120s watchdog killed scans). Full-scan cooldown uses Sku's own 16-min timer, not CanSendAuctionQuery's unreliable getAll flag.
- QueryResultsDB/FullScanResultsDB/FullScanResultsDBHistory/AuctionDBHistory are intentionally global (no `local`) — other code and the serializer reach them by name; adding `local` would silently fork them.
- File starts with UTF-8 BOM; parse with encoding='utf-8-sig'.
