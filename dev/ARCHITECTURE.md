# Sku — Architecture & Developer Guide

Sku is a World of Warcraft addon that provides a complete screen-reader
interface (NVDA / JAWS) for blind and visually impaired players. This document
is a map of the codebase and its dev tooling — useful onboarding for anyone
(human or AI assistant) working on the addon. It targets the TBC Anniversary
client (Interface `20506, 11508` — TBC 2.5.6 + Era 1.15.8).

## Architecture

Sku is built on **Ace3** (AceAddon, AceEvent, AceConfig, AceComm, etc., under
`Sku/Libs/`). Load order is defined in `Sku/Sku.toc`. SavedVariables:
`SkuOptionsDB`, `SkuTranslatedData`, `SkuErrorLog`. Settings live in deeply
nested tables under `SkuOptionsDB` (e.g. `SkuOptions.db.char[module]...`); the
menu UI is generated by `SkuZOptions`.

Module folders (each typically has `Core.lua` + `Options.lua`):

- `SkuDispatcher/` — event broker, used as a **deliberate hybrid**, not a single
  mandatory bus. Two jobs: (1) the `SKU_*` custom events are the cross-module
  publish/subscribe channel; (2) `RegisterEventCallback` fan-out for raw WoW
  events is used by the **SkuCore object family** (Core, aqCombat, aq,
  DialTargeting, turnToUnit, skuFocus), because several SkuCore sub-files must
  subscribe to the *same* WoW event and one AceEvent object can't. Every OTHER
  module registers its own WoW events directly via its own AceEvent object —
  that is idiomatic Ace3 and intended (per-module lifecycle ownership).
- `SkuCore/` — the bulk of features (one file per feature): `aq.lua` /
  `aqCombat.lua` (health & combat monitoring), `gameWorldObjects.lua`,
  `minimapScanner.lua`, `auctionHouse.lua`, `mail.lua`, `friends.lua`,
  `voiceOutput.lua`, `UIErrors.lua`, `DialTargeting.lua`, `turnToUnit.lua`,
  `equipmentSets.lua`, `Build_SocketingFrame.lua`, `dungeonBrowser.lua`, etc.
- `SkuDB/` — static game database (maps, creatures, items, quests, spells,
  objects, polygons, waypoints), split by content: base/TBC + `WotLK/` + `SoD/`.
  These are large generated `assets/` tables (not version-controlled — see
  "Repo layout").
- `SkuNav/` — audio-beacon navigation (routes, waypoints, minimap nav `SkuMM`).
- `SkuQuest/` — quest tracking/announcement.
- `SkuAuras/` — aura/buff/debuff tracking, role detection, aura sharing.
- `SkuMob/` — target/mob tracking.
- `SkuChat/` — chat accessibility.
- `SkuZOptions/` — settings/menu system, voice config, keybinds
  (`SkuKeyBinds.lua`), templates, utilities (the menu-builder framework).
- `SkuAudioData/` — audio file index/length tables for voice output.
- `Libs/` — Ace3 plus Sku's own libs: `SkuTTS-1.0`, `SkuVoice-1.0`,
  `SkuBeacon-1.0`, `LibRangeCheck-3.0`, `LibGearScore-1.0`.

## Repo layout & asset policy

- The addon source lives under `Sku/` (`Sku/Sku.toc`, `Sku/SkuCore/`,
  `Sku/Libs/`, ...). This is the addon root that WoW loads.
- `Sku/.gitignore` excludes bulky **binary assets** (`*.mp3`, `*.ogg`, fonts,
  images) and **large generated game-data tables** (`routedata_global_wotlk.lua`,
  everything under `SkuDB/assets/`). These are ~290 MB and ship inside the
  release ZIPs; they are not tracked here. To run from a source checkout, overlay
  the asset files from a release ZIP into `Sku/`.
- `Sku/.gitattributes` forces LF so diffs stay clean.
- Companion addons (distributed separately, not in this repo): `SkuBeaconSoundsets`
  (a hard TOC dependency), plus `SkuNavData`, `SkuHealthAssets`, and the
  `SkuAudioData_*` language pack.

## Logging — two stores, pick the right one

Sku persists two separate logs, both as globals inside the same
`SavedVariables/Sku.lua` (neither is its own file).

**1. `SkuDebugLog` — the GENERAL debug ring (read this for most traces).**
`dprint(...)` (`Sku/Core.lua`) is the project's general logger. When enabled it
appends each call to `SkuDebugLog.lines` (a ring of up to 2000 entries). Each
entry is flat — `seq` (monotonic), `t` (`HH:MM:SS`), `msg` (all args joined;
table args shallow-serialised one level deep as `{k=v, ...}`). Most module
breadcrumbs live here (auction buy/scan/sell, dungeonBrowser, sockets,
talentSwitch, atlas.menu, menu.reanchor, etc.).
- Enable in-game: `/skudebug log on` (silent, persists) or `/skudebug on`
  (chat + log), or cycle the `SKU_KEY_DEBUGMODE` keybind (off → log only →
  print only → print+log → off).
- `Sku.debug = {print=, log=}`: `print` echoes to the chat frame, `log` writes
  the ring. Both default **OFF and reset to OFF every load** — the captured DATA
  persists across `/reload`, the on/off STATE does NOT, so re-enable each
  session. `/skudebug` (no args) reports the flags; `/skudebug clear` empties the
  ring; `/skudebug show` prints the last 10.
- Turning logging on writes a marker line `=== log enabled ... ===`. Everything
  after the last marker is the current run.
- `dprint` is cheap when off (one flag check; no `debugstack`, no context).

**2. `SkuErrorLog` — ERRORS + a few deliberate diagnostics.** The error-capture
system (`SkuCore/ErrorLog.lua`) chains the Lua error handler and auto-logs
`LUA_WARNING` / `ADDON_ACTION_FORBIDDEN`/`BLOCKED`, deduped by fingerprint with
per-event context and a combat throttle. Two stores:
- **`SkuErrorLog.recent`** — chronological ring (last 500): `seq`, `t`, `source`,
  `message`, `stackHead`, `session`. Read this for an error timeline.
- **`SkuErrorLog.unique`** — deduped by message+top-stack fingerprint (`count`,
  `firstSeen`, `lastSeen`, full `stack`, `firstCtx`/`lastCtx`). Use for "how
  often / full stack of a message".
- In-game: `/skulog show` (last 10), `/skulog export`, `/skulog clear`.

Both logs are multi-line Lua tables (one field per line), so a single-line
`grep` can't reconstruct a record — parse by locating the table's `Name = {`
line, capturing the block by brace-depth counting, then reading fields by
scanning stripped lines.

## Syntax-checking Lua edits

The `luaparser` Python package can syntax-check before a `/reload`:

```
py -3 -c "from luaparser import ast; ast.parse(open('Sku/SkuCore/auctionHouse.lua', encoding='utf-8-sig').read()); print('OK')"
```

Use `encoding='utf-8-sig'` — Sku's Lua files start with a UTF-8 BOM the parser
otherwise chokes on. This validates syntax only (not runtime/logic or WoW API
use), so it's a first gate, not a substitute for the in-game test.

## Dev tooling in this repo

- `dev/rework-docs/` — design/reference docs (route/DB/menu plans, KNOWN-ISSUES,
  perf notes, audits) plus ~50 reusable Python helper tools: log/error/perf-ring
  readers, DB manifest/convert scripts, locale scanners, codemods. Reuse these
  before writing new ones.
- `dev/llm/` — an LLM-oriented index/analysis set (auction-house deep-dives,
  cross-project comparisons, improvement plans) for fast codebase navigation.

## Related project

`WowVision` is a separate accessibility addon (different architecture:
middleclass/InfoClass). Its `tbc/sku/` folder is a **port** of some Sku features
