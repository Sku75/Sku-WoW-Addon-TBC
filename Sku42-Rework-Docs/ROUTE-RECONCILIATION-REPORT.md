# Route reconciliation report — base vs WotLK, per zone

Date: 2026-07-08. Read-only analysis. Generated by
`scratchpad/analyze_stranding.py` from `Sku/SkuDB/assets/routedata_global.lua`
(base) and `Sku/routedata_global_wotlk.lua` (wotlk), names from `maps.lua`.

Purpose: decide, per zone, which route file is authoritative for the TBC client —
and quantify what the current runtime hybrid (base **waypoints** + WotLK **links**)
costs. Nothing here is changed; this is the decision input.

## Method (what the numbers mean)

- The hybrid uses base waypoints but WotLK links. A WotLK link survives only if
  both its endpoints resolve to a base waypoint of the same zone; otherwise Sku
  silently prunes it. "stranded" = WotLK links pruned this way.
- Only CUSTOM waypoints come from these files and can break. Creature/object
  link endpoints come from the shared SkuDB (identical either way) and are
  excluded from stranding.
- "base_own_links" = how many links base's OWN self-consistent set would give
  that zone (i.e. what we'd have if we used base links instead of WotLK there).

## Headline

- WotLK link-assignments total: **192,084**. Resolved by the hybrid: **189,498**.
  **Stranded (pruned): 2,586 = 1.3%.** The hybrid is fine in ~98.7% of the world.
- Stranding is concentrated: **Western Plaguelands alone accounts for 1,466
  (57%)**; then Netherstorm 374, Icecrown 233, Stormwind 166, Hrothgar's Landing
  111, Eastern Plaguelands 60. Everything else is < 60.
- The bigger, invisible cost is NOT stranding but the hybrid using the WRONG
  file for a zone (see Eastern Plaguelands below): base has a rich route graph
  the hybrid throws away.

## The pattern that matters

Base is the authority for CLASSIC Eastern Kingdoms zones; WotLK is the authority
for NORTHREND/expansion zones. The hybrid picks WotLK links everywhere, which is
right for the expansion zones and WRONG for a few classic EK zones.

**Crucial for the TBC (2.5.6) client:** Northrend is NOT reachable on TBC, so the
WotLK-richer Northrend zones (Icecrown, Dragonblight, Storm Peaks, Grizzly Hills,
Hrothgar's Landing, Dalaran) are dead weight — their stranding/richness doesn't
affect a TBC player. Only Eastern Kingdoms, Kalimdor and Outland matter.

## On your "more but broken" concern

The risk of shipping WotLK waypoints that don't exist on TBC is real but SMALL and
localised. The big WotLK-only waypoint counts are all in Northrend (unreachable,
so moot). In the TBC-reachable world the only non-trivial WotLK-only additions are
Netherstorm (117) and Stormwind (66); everything else is single digits. So a
"prefer WotLK where richer" policy would only need a spot-check of two zones, not
the whole world.

## Options (no change made — your call)

1. **Targeted fix (lowest risk, biggest win):** for the handful of base-richer
   classic zones — Eastern Plaguelands and Western Plaguelands above all — use
   base's OWN links instead of WotLK's. Fixes the worst degradation, touches

2. **Collapse to base, self-consistent (simple, probably best for TBC):** drop

   (unreachable) Northrend routing. Given base is the newer/fuller snapshot for
   the reachable world, this is likely a net win for TBC end users.
3. **Source a clean single-version file** (your idea) and skip the merge entirely.
4. **Do nothing:** the hybrid is 98.7% fine; only the Plaguelands are badly hurt.

## Timeline caveat — "fuller" is not "TBC-correct"

The Anniversary realm runs a CYCLICAL timeline (Era → TBC → WotLK → loops back to
Era → …) and we are on **TBC, which is BEFORE WotLK**. Maps genuinely change between
phases (e.g. Eastern Plaguelands had the Death Knight "Scarlet Enclave" carved out in
WotLK). So the WotLK route file is a FUTURE / different map state, and the correct
data for a zone is the one matching the CURRENT phase (TBC) — NOT simply the file
with more waypoints. This qualifies the options above:

- "Collapse to base" (option 2) fixes the link-starvation and is the fuller data,
  but base being fuller does NOT guarantee it is TBC-accurate — some of its extra
  waypoints could be WotLK-era placements pointing at things that don't exist on TBC
  yet (the user observed exactly this: an EPL waypoint aiming at a WotLK-only
  feature). The file labels can't be trusted at face value (base EPL 1,527 is fuller
  than the wotlk file's 151 — the opposite of "wotlk added more").
- So before shipping any collapsed/merged set, the base-richer changed zones
  (Eastern/Western Plaguelands above all) should be **spot-checked against the TBC
  map**, not accepted just because they have more points. Sourcing a known
  TBC-phase route set (the "non-mixed file" idea) sidesteps this entirely.
- Longer term, correct handling is per-phase route selection (the addon picks the
  data matching the running client's phase), which does not exist today. See
  the timeline note in the SkuMapper audit and project memory.

## Live confirmation (EPL) + /skuzoneprobe — 2026-07-08/09

Added a read-only diagnostic **`/skuzoneprobe`** (`/szp`) in `Sku/SkuNav/Geo.lua`
(commits 787aba0, 21171eb, d6c828b). It dumps, for the player's position: the
client's real `uiMapID` (`C_Map.GetBestMapForUnit`) + the real AreaTable ids
(`C_MapExplorationInfo.GetExploredAreaIDsAtPosition`, each named via
`C_Map.GetAreaInfo`) vs what SkuNav resolves (`GetCurrentAreaId`), plus
**loaded** (`SessionRouteData`) and **survived** (`WaypointCache` after cleanup)
route-waypoint counts for the current area AND its parent zone. It writes to the
`SkuDebugLog` ring (read back after the last `=== skuzoneprobe` marker), so no
chat pasting. Note: the client's zone DATA is in DB2 files, not the interface Lua;
the live `C_Map` API is the only ground truth.

Result standing in Eastern Plaguelands (Chapel of the Hopeful Light):

- **Numbering is consistent — no cross-cycle renumber.** Client AreaTable id 2268
  == Sku areaId 2268; uiMap 1423 both sides; parent 1415. `uiMap OK` / `areaId OK`.
  Sku's areaId scheme IS the client's AreaTable scheme on this client.
- **The hybrid destroys 100% of EPL's custom routes.** Parent zone 139 reported
  **`loaded 1527 -> survived in cache 0`**: the base data loads all 1,527 EPL
  waypoints, the WotLK link set resolves none of them (array positions differ),
  and `CleanupWaypoints` deletes every zero-link custom waypoint — all 1,527. So
  it is 1527 → 0, not the "~120 survive" earlier estimated.
- **What's left (the "few points, one WotLK-only") = creature/object auto-waypoints**
  (typeId 2/3), which come from the shared TBC+WotLK-merged SkuDB, not the route
  files, so cleanup never touches them; some are WotLK-only NPCs with an EPL spawn.
- Aside: the current area resolves to the **sub-area** the player stands in (from
  the minimap zone text), e.g. chapel 2268 — nav granularity is sub-area, not zone.

This confirms end-to-end the mechanism in §7.4/2.7: base is the authored map for
TBC-reachable zones, but because the hybrid supplies WotLK links, cleanup deletes
those zones' whole custom route net at load (EPL total; WPL/Swamp/Westfall partial).
