# SkuNav/Core.lua

- Purpose: The heart of Sku's audio-beacon navigation. It builds and owns the in-memory WaypointCache (~145k records from SkuDB creatures/objects plus custom route waypoints), manages the bidirectional waypoint-link graph (routes), computes metapaths (multi-hop routes via breadth-first relaxation over links), and drives the live navigation loop (beacon start/stop, direction/distance announcements, waypoint-reached detection, route following, route recording via mouse on the SkuMM map). [W6-B #16] The stateless geo/map-math service was EXTRACTED to SkuNav/Geo.lua (GetBestMapForUnit, area/uiMap id conversions, GetDirectionTo, Distance, GetContinentNameFromContinentId, GetDirectionToAsString, IntersectionPoint, etc.); Core now retains only the state-coupled geo helpers (GetWorldCoordinatesFromZone — mapData; GetDirectionToWp / GetDistanceToWp — WaypointCache) plus the SkuNav.Geo facade table that re-exposes the extracted 12 for SkuQuest/SkuCore/SkuMob. It is an AceAddon module ("SkuNav", AceConsole+AceEvent); menu/UI lives in SkuNav/Options.lua and the map viewer in SkuNav/SkuMM*.

## Key data structures
- WaypointCache (file-local array) — record per waypoint. Slim records (DB rework lever A+B): only name, wpId, typeId, areaId, worldX, worldY stored (+role for NPCs, +comments/createdBy/size on custom wps when non-default, +links only once linked). WpRecordMT.__index derives the missing fields via WpDerivedFields: dbIndex/spawn decoded from the bit-packed wpId, spawnNr = spawn, uiMapId from areaId (memoized), contintentId (sic, misspelled everywhere) from InternalAreaTable, createdAt = build time, createdBy = "SkuNav", size = 1, role = "". Writes shadow the derived defaults per record.
- WaypointCacheLookupAll (name → cache index; last-wins on duplicate names = the canonical record), WaypointCacheLookupIdForCacheIndex (wpId → cache index), WaypointCacheLookupPerContintent (continentId → {cacheIndex → name}). All file-local and re-ASSIGNED (new tables) on every rebuild — never cache references externally; DevGetWaypointCacheTables rebuilds its map per call for that reason.
- WpEmptyLinks — ONE shared read-only {} with an erroring __newindex, answered as .links for every never-linked record; writers must call WpEnsureLinks(record) to materialize a real {byId={cacheIdx→distance}, byName={name→distance}} per record first.
- wpId bit layout: dbIndex bits 1-20 (custom 0-199999, creatures +200000, objects +500000), areaId bits 21-38, spawn bits 39-48. wpIds key the persisted link DB.
- SkuDB.SessionRouteData — session working copy of the route DB: .Waypoints (array; index = dbIndex = wpId payload for custom wps; deleted entries become {false} tombstones — positions are load-bearing, never compact) with per-entry names={enUS,deDE}, contintentId, areaId, worldX/Y, createdAt/By, size, comments/lComments; .Links (sourceWpId → {targetWpId → distance}, symmetric).
- Build machinery: SkuNav._wpcCo (coroutine; also this module's registered build-worker liveness probe), _wpcGen (generation counter to drop superseded pumps), wpcPendingArgs (deferred-build args; the #15 registered build step re-issues them the moment creatures+objects are ready), wpCacheReady flag, tWpcBudgetMs (now delegates to the shared Sku:BuildFrameBudgetMs arbiter → 75 ms while the SkuDB stream also runs, 150 alone — fixed total by user choice), tWpcPhaseMs per-phase profiling (result → SkuDebugLog.wpcResult), tWpcMapTransform (per-uiMapId affine transform derived from 3 probes + verified by a 4th; false = fall back to per-spawn C_Map call).
- mapData/worldMapData/transforms — inlined HereBeDragons-style map geometry, built lazily by buildMapData() on first GetWorldCoordinatesFromZone miss.
- Metapath state lives in settings (see below): metapathFollowingMetapaths is {targetName = {distance, distanceToStartWp, pathWps={names...}}} plus mixed array-part entries.
- SkuNav.ReverseRt = {meta = {metapathFollowingStart/Target/Metapaths/CurrentWp}, single = {}} — reverse-route snapshot updated on every route wp advance.
- GetNpcRolesCache — simple memo table (npcFlags→role; stayed in Core). GetUiMapIdFromAreaIdCache moved to SkuNav/Geo.lua with GetUiMapIdFromAreaId in #16.

## Invariants & gotchas
- Coroutine build: NEVER yield inside pcall in the build path (project-wide lesson from the instance-reload crash). tWpcYield is a deliberate no-op outside the build coroutine so the same helpers (LoadLinkDataFromProfile etc.) serve synchronous callers unchanged. The pass ORDER creatures → objects → custom → links must be preserved: the custom pass's name-collision merge and link resolution depend on prior state. tWpcHardYield exists to keep the slice clock and phase buckets honest — do not replace with bare coroutine.yield().
- CreateWaypointCache silently DEFERS (sets wpcPendingArgs) until skudb.creatures+objects are data-ready; the ChunkLoader master sequence re-issues it. Anything needing the complete cache early must call EnsureWaypointCacheComplete (which also force-finishes the chunk stream).
- WpEmptyLinks is shared by ~94k records: reading .links.byId on an unlinked record is fine (nil), but writing into record.links without WpEnsureLinks corrupts every unlinked waypoint at once (trapped by __newindex error). SetWaypoint line 3987 uses rawget for exactly this reason.
- The cache lookup tables are file-locals re-assigned on rebuild; only access them through SkuNav methods.
- wpId bit widths (20/18/10) and the type base offsets encode into the PERSISTED SessionRouteData.Links keys — changing them breaks every saved route.
- SessionRouteData.Waypoints: dbIndex = array position is load-bearing (wpId payload); deletions tombstone with {false}, never compact/table.remove.
- Lever E (LoadDefaultMapData, lines 3713-3733): on TBC the live tables are SkuDB Waypoints + SkuDBTMP Links; the dead twins are freed and CANNOT be rebuilt without /reload (EnsureData nils the builders) — every route-data reset path must go through LoadDefaultMapData, never hand-wire SessionRouteData.
- SetOverrideBindingClick/ClearOverrideBindings are combat-protected: CreateSkuNavMain (OnEnable) and the OnDisable teardown are both gated on SkuState:IsInCombat() == false.
- hasCustomMapData (global scope) gates whether PLAYER_LEAVING_WORLD wipes SessionRouteData — it is set true by every map-edit path; missing it in a new edit path silently loses user edits on logout.
- The build budget (150 ms/frame TOTAL, split to ~75 each while the SkuDB stream also runs) is a deliberate user decision — do not "fix" the low fps during the post-login build. [W6-B #15] the split is now computed by the shared Sku:BuildFrameBudgetMs arbiter (each worker registers its own liveness probe), not by the two sides peeking at each other's coroutine.
- comments deliberately has NO derived default (a shared table would be mutated by all records); consumers must nil-check.
- Localized route wp names are packed "en§de" in routedata and split in LoadDefaultMapData (line 3697).
- OnDisable disarms lifecycle only; the geo/query methods stay callable while disabled because SkuQuest/SkuCore/SkuMob depend on them.
